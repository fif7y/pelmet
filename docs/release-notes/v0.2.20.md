# Pelmet 0.2.20

Some icons can't be hidden. A few apps draw their menu bar icon from a
helper that macOS doesn't count as an app, so there's nothing for a hide
to act on. ChatGPT Classic is the best known one. Pelmet could move that
icon around but never conceal it, and the editor had no way to tell you
why.

This release turns that into a feature.

Added:

- App launchers. A Pelmet icon that opens any app, and hides like any
  other icon. Pick an app in Settings > Menu Bar > App launchers and
  choose whether it always shows or only while the app is running. Give it
  any icon you like: the app's own, or one of about 7,000 system symbols
  with search. Click opens the app, right-click quits it.
- For the icons that can't hide, the editor now says so. They show dimmed
  with a "!" mark, and hovering explains the cause with an "Add a
  launcher" button right there. Add the launcher, turn the original icon
  off in the app's own settings, done.
- Launchers aren't only for problem apps. One parked in a hidden section
  is a quiet way to reach an app you open now and then.
- The input source menu (the keyboard and language item) can now be
  managed like any other icon. Thanks to keyding for the contribution,
  Pelmet's first outside pull request.

Fixed:

- When a section in the editor wraps onto two lines, it now wraps the way
  the menu bar reads. The top line keeps the icons nearest the clock, and
  it's the leftmost ones that move down. Drops in a wrapped section land
  where the pointer is.
- Launcher icons appeared too big and cut off on an external display. The
  menu bar is taller on a MacBook's built-in screen than on most monitors,
  and the icon was sized for the tall one.
- Turning the input menu off in System Settings left a stale tile in the
  editor.
- Restarting one of macOS's own menu bar agents made the hidden icons
  flash twice.
- An icon read on the wrong side of the chevron during a single pass no
  longer changes sections. Pelmet waits for two passes that agree.
